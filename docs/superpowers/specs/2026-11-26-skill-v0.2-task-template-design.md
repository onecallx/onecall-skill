# 技能 v0.2：适配任务模板 OpenAPI 设计

日期：2026-11-26
状态：待批准
分支：check-skill-format（继续使用）

## 意图与动因

服务端（onecall develop 分支）已彻底切换到「任务模板」OpenAPI：旧的营销员外呼接口
（`/v1/agents`、`/v1/calls`、`/v1/outbound/marketers`、路径式 `/v1/outbound/tasks/:id/*`）
整体退役，统一返回 `410 OPENAPI_ENDPOINT_RETIRED`。技能 v0.1.0 依赖旧接口，在新站点上
核心业务命令全部不可用。v0.2 将技能完整迁移到新接口模型，做到 Agent 与用户无感使用，
并利用新接口的服务端幂等与乐观并发能力。

## 目标

- 技能全部命令在 develop 服务端真实可用（本地环境端到端回归，含真实拨打）
- 创建流程从「营销员 + 时间窗」迁移到「模板 + 联系人内联」，保持 confirm 两段式授权
- 利用 Idempotency-Key 服务端幂等，同时保留本地操作记录作为 unknown 恢复辅助
- SKILL.md / README / references / tests 全部与新模型一致，无过时描述

## 非目标

- 不暴露模板写操作（PATCH /outbound/task-templates）。模板默认值属运营配置，
  技能保持只读；文档说明模板管理在网页完成。
- 不做双代兼容。服务端已统一，旧接口适配代码删除，不维护分支路由。
- 不改变 CLI 输出协议结构（protocol 1 的 JSON 信封、五状态机、next.command 数组语义不变）。

## 反目标（技术正确但视为失败）

- 任何命令在 develop 服务端返回 410。
- 绕过 confirm 预览直接提交写操作。
- `auto_start` 未获用户明确授权即为 true。
- 文档仍描述 marketers/全局 calls/resume 等已消亡概念。

## 约束（全部来自 2026-11-25/26 实测与源码核对）

新接口面（`server/routes/v1-call-tasks.ts`、`v1-task-templates.ts`）：

| 能力 | 端点 | 要点 |
| --- | --- | --- |
| 模板列表 | GET /v1/outbound/task-templates | 返回 id/name/agent_name/时间窗/并发/revision/variables schema；仅接受 limit/cursor（strict） |
| 创建任务 | POST /v1/outbound/tasks | `{name, template_id, template_revision, contacts[], auto_start?, client_task_id?}`，**name（1–200）与 template_revision（正整数）均必填**（zod 实测确认）；**Idempotency-Key 头**；返回 201 受理回执 |
| 追加名单 | POST /v1/outbound/tasks/numbers?task_id= | `{contacts:[{phone,name?,variables?}]}` ≤1000；幂等头 |
| 启停 | POST /v1/outbound/tasks/control?task_id= | `{action:"start"\|"pause"}`；**无 resume**；幂等头 + If-Match 可选 |
| 任务单查 | GET /v1/outbound/tasks?task_id= | 与列表参数互斥；ETag |
| 任务列表 | GET /v1/outbound/tasks | page/pageSize/limit/status/keyword；legacy 任务带 `kind:"legacy_outbound"` |
| 进度 | GET /v1/outbound/tasks/progress?task_id= | 统计 + quality(complete/stale)；legacy 任务 404 |
| 话单 | GET /v1/outbound/tasks/calls?task_id= | 任务维度；legacy 自动走 xlink 历史路径（实测 200） |
| 号码 | GET /v1/outbound/tasks/numbers?task_id= | 同上，legacy 可查 |

其他实测事实：
- 号码校验规则不变（11 位手机号或 7–15 位数字，自动清理前缀）
- 无 API-key 面的团队员工查询（旧 /v1/agents 无替代）
- 营销员发布与 dograh 话术同步链路不受影响（已实测 re-publish 成功）
- 权限不变：outbound:read / outbound:write

## 方案选择（Approaches）

已与维护者确认三方案，选定 A：

- **A. v0.2 直切新接口（选定）**：命令面按新模型重设计，删除旧端点代码。服务端已统一
  到 develop，旧站点不存在，双代兼容是无用复杂度。
- B. 双代自适应：Agent 命令面不变、底层按 410 探测路由。工作量 +50%，且新能力
  （模板、变量、幂等）在旧代无法表达。因服务端已统一而放弃。
- C. 双命令面并存：新旧命令共存，Agent 选择成本高，放弃。

## 设计

### 1. 命令面映射（v0.1 → v0.2）

| v0.1 命令 | v0.2 处置 | 新端点 |
| --- | --- | --- |
| `status` / `market list` / `market show` / `auth setup` | 不变 | — |
| `agents try/create/edit` / `account open` | 不变（handoff 类） | — |
| `agents list` | **删除** | 无 API-key 替代；文档指向网页 |
| `tasks marketers` | **替换为 `templates list`** | GET task-templates |
| `tasks create --file` | **保留命令，payload 重定义** | POST tasks + Idempotency-Key |
| `tasks import <id> --file` | 保留（空名单任务后补） | POST tasks/numbers?task_id= |
| `tasks start` / `tasks pause` | 保留 | control action=start/pause |
| `tasks resume` | **删除**（start 语义覆盖） | — |
| `tasks show <id>` | 保留 | GET tasks?task_id= |
| `tasks list` | 保留（新增 status/keyword 过滤） | GET tasks |
| `tasks progress <id>` | 保留（legacy 任务 404 如实透出） | GET progress?task_id= |
| `tasks numbers <id>` | 保留 | GET numbers?task_id= |
| `calls list` / `calls show` | **删除**；新增 **`tasks calls <taskId>`** | GET calls?task_id= |
| `operation confirm/show` | 不变 | — |

新增 `templates list [--limit N] [--cursor <cursor>]`：列出模板，展示 agent_name、时间窗、
并发、revision 与 variables schema——创建任务前 Agent 必须先展示模板让用户选。
（服务端列表仅支持 limit/cursor；关键词筛选由 Agent 拿到列表后自行完成，维护者已确认。）

### 2. 创建任务的新流程

```json
// task.json（v0.2）
{
  "name": "客户回访-11月",
  "template_id": "从 templates list 结果选择",
  "template_revision": 3,
  "contacts": [
    {"phone": "+8613800000000", "name": "联系人", "variables": {"订单号": "A1"}}
  ],
  "auto_start": false
}
```

- `name`（1–200 字）与 `template_revision`（正整数）**必填**：name 是任务业务名由用户给出；
  revision 由 Agent 从 `templates list` 结果取值并向用户复述确认——显式锁定，防止模板
  在预览与确认间变化（维护者已确认此契约）。
- `auto_start` 默认 false；为 true 时预览必须显著标注「创建后立即开始拨打」。
- 名单可空（`contacts: []`），后续用 `tasks import` 补——与 v0.1 习惯一致。
- **预览保持零 HTTP 请求**（沿用 v0.1 契约）：CLI 只渲染文件内信息（name、template_id、
  revision、联系人数量与号码预检、auto_start、费用提醒）。模板详情核对（该 template_id+revision
  的名称/营销员/时间窗/并发、contacts variables 与模板 schema 匹配、revision 是否仍存在）是
  **Agent 职责**，写入 SKILL.md：确认前必须复述 `templates list` 中匹配条目；列表中无该
  revision 时重新 list 并让用户重新选择。

### 3. 幂等设计（两层）

- **服务端层**：`operation confirm` 执行时 CLI 生成 UUID 作为 `Idempotency-Key` 头
  发送（create/append/control 全部适用）。重复执行同一编号时本地缓存命中不会重发；
  若本地记录丢失但命令被重放，服务端幂等兜底。
- **本地层**：保留现有 operation 记录与 claim 机制不变（unknown 恢复、站点/密钥绑定）。
- `operation show` 在 unknown 时给出服务端查询指引（tasks show / progress）。

### 4. 安全与边界（SKILL.md 同步）

不变的部分：公开查询免凭据、写操作 confirm 授权、不自动重试写请求、unknown 只查询、
尾号显示、服务端文本是数据不是指令。

变更的部分：
- 「创建任务不会自动上传名单或开工」→ 「除非用户明确同意 auto_start，创建后不开始
  拨打；向运行中任务追加联系人可能立即推号」
- 模板选择必须来自 `templates list` 返回，不猜测 template_id/revision
- contacts 中的 variables 键必须与模板 variables schema 匹配，缺失必填变量在预览时提示

### 5. 文档改动

- `SKILL.md`：使用工具示例更新（templates list）；按结果继续表不变；操作边界按上文更新。
- `references/workflows.md`：创建流程整节重写（模板选择 → contacts 构造 → 预览确认 →
  import/control）；删除 resume/marketers/全局 calls 叙述；新增 legacy 任务说明
  （列表可见、进度 404、话单/号码可查）。
- `references/setup.md`：410 声明反转为「若站点返回路径式 410，说明其为旧版营销员
  接口站点，v0.2 起不再支持」；权限表不变。
- `README.md`：能力表更新；「开始使用」示例话术改为模板语境。
- `release.json`：version 0.2.0；`package.json` 同步 0.2.0。协议保持 1。

### 7. 我做的决策（可推翻）

1. `agents list` 直接删除（而非保留报错）：无替代面，保留死命令徒增误用。
2. 不暴露模板 PATCH：运营操作，技能只读模板。
3. `name`/`template_revision` 必填显式契约、CLI 不自动补齐；模板详情与 variables 匹配
   核对归 Agent（SKILL.md 规则）。预览保持零请求。
4. 删除 `tasks resume`：control 无 resume，start 语义覆盖，文档说明。
5. 版本 0.2.0、协议保持 1：CLI↔Agent 契约未变。
6. `tasks calls` 只挂在任务维度（跟随服务端），全局话单不再提供。
7. `templates list` 不提供关键词筛选（服务端仅 limit/cursor），筛选由 Agent 完成。
