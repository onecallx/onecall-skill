# OneCall 电话数字员工 Skill

在支持 Agent Skills 和本地命令执行的 AI 助手中查找电话员工、查询任务与话单，并在确认后管理外呼任务。

当前版本 **0.2.0** · 协议 **1** · 运行环境 **Node.js 20+** · 无第三方依赖，无需安装全局 CLI

## 功能概览

| 功能 | 方式 |
| --- | --- |
| 搜索公开数字员工、查看详情与试听入口 | 直接查询，无需 API Key |
| 创建员工、调整配置、体验语音或电话 | 返回 OneCall 网页入口，在网页完成 |
| 查询任务模板、任务、进度、号码与话单 | 使用团队 API Key |
| 基于模板创建任务、导入 JSON 联系人、启停外呼 | 先预览，授权后确认提交 |

## 安装

把这句话发送给支持本地工具执行的 AI 助手：

```text
请帮我安装 OneCall 电话技能：https://github.com/onecallx/onecall-skill
先读取 SKILL.md，保留完整目录。
```

也可以手动克隆到宿主支持的 Skills 目录。下面以 Codex 为例（已有同名目录时先核对本地修改）：

```sh
git clone https://github.com/onecallx/onecall-skill.git ~/.codex/skills/onecall-phonecall
```

Claude Code、WorkBuddy、OpenClaw 的常见目录见[安装与配置](references/setup.md)。Cursor 使用其实际配置的 Skills 目录。安装后重新加载技能或新开对话。仅支持网页聊天、不支持本地命令的工具无法直接运行本 Skill。

## 连接 OneCall

下面以 Codex 为例（其他宿主替换为实际安装路径）：

```sh
node ~/.codex/skills/onecall-phonecall/scripts/onecall.mjs status
node ~/.codex/skills/onecall-phonecall/scripts/onecall.mjs market list --q 回访
```

- **公开查询无需密钥**；团队操作需要 API Key（见[配置 API Key](#配置-api-key)）。`status` 只检查本地配置，不代表服务器授权成功。
- 本 Skill 依赖服务端的任务模板 OpenAPI（`/v1/outbound/task-templates`、查询参数式 `/v1/outbound/tasks*`）。若 `templates list` 持续 404、且 `tasks list` 返回条目不含模板字段（无 `state_version`），说明站点可能仍是旧版营销员接口，本版本已不再支持——请升级站点，详见[安装与配置](references/setup.md)。
- 最小权限：查询 `outbound:read`；写入（创建、追加联系人、启停）再加 `outbound:write`。

## 配置 API Key

团队功能（模板、任务、外呼）需要 API Key；公开市场查询不需要。首次配置后无需重复。

### 1. 创建密钥

登录 [OneCall 开发者页](https://app.16x.tech/developer) 创建 API Key（`sk_live_` 开头），按用途勾最小权限：查询 `outbound:read`，要做外呼再加 `outbound:write`。

### 2. 配置到本机（三选一）

| 方式 | 用的变量 | 密钥实际存哪 | 关掉终端后 | 适合 |
| --- | --- | --- | --- | --- |
| A · 环境变量 | `ONECALL_API_KEY` | 只在当前终端内存里 | 失效，要重设 | 临时试一下 |
| B · 私密文件（推荐） | `ONECALL_CREDENTIALS_FILE` | `~/.onecall/creds.json`（0600） | 文件还在，重设路径变量即可 | 长期使用 |
| C · 助手代配置 | 同 B | 同 B | 同 B | 省事 |

两个变量名作用不同：`ONECALL_API_KEY` 直接存密钥本体；`ONECALL_CREDENTIALS_FILE` 只存一个指向私密文件的路径。

**方式 A · 环境变量**（macOS/Linux，只对当前终端有效）：

```sh
export ONECALL_API_KEY="sk_live_你复制的密钥"
```

**方式 B · 私密文件**（推荐；技能会校验权限必须 0600，不对会拒绝读取）：

```sh
# 1. 建目录（已存在也不报错）
mkdir -p ~/.onecall
# 2. 写入密钥（必须是 {"apiKey":"…"} 结构）
printf '{"apiKey": "sk_live_你复制的密钥"}' > ~/.onecall/creds.json
# 3. 收紧权限（必须）
chmod 600 ~/.onecall/creds.json
# 4. 告诉技能文件在哪（变量存路径，不是密钥）
export ONECALL_CREDENTIALS_FILE="$HOME/.onecall/creds.json"
```

**方式 C · 发给助手代配置**：把下面这段复制发给 AI 助手，替换密钥占位符即可：

```text
这是我的 OneCall API Key：sk_live_把这里替换成你的密钥
帮我配置好，配好了告诉我怎么验证。
```

助手会把它写入 `~/.onecall/creds.json`（0600），全程不回显密钥（仅显示尾 4 位核对），不写入 shell 启动文件、不提交仓库。配置后发送 `看下配置状态` 验证。注意：密钥会留在对话记录里，介意的话到开发者页吊销重建，再更新 `creds.json` 即可。

### 3. 持久化、换密钥与 Windows

- **每次自动生效**：方式 A 把 `export ONECALL_API_KEY=…` 写进 `~/.zshrc` / `~/.bashrc`；方式 B 写入的是 `export ONECALL_CREDENTIALS_FILE=…`（**路径**，密钥本身留在文件里，别把密钥写进 rc 文件）。
- **换密钥**：网页吊销旧的 → 方式 A 重设一次变量；方式 B 只替换 `creds.json` 里的密钥（权限保持 0600），其他不动。
- **Windows**：方式 A 用 `setx ONECALL_API_KEY "sk_live_…"`（新开终端生效）；方式 B 在 PowerShell 里 `$env:ONECALL_CREDENTIALS_FILE="C:\Users\你\.onecall\creds.json"`（文件需仅当前用户可读，icacls 设置）。

### 4. 验证与安全

发送 `看下配置状态`，返回密钥已配置即完成（权限校验由服务端在首次团队查询时执行）。

安全三原则：密钥**不粘贴进对话**、**不提交进仓库**；疑似泄露时在开发者页**吊销重建**，更换后仅需更新本机配置。

## 快速开始

直接用自然语言描述电话业务需求即可触发本技能，无需先提到 OneCall：

```text
帮我找一位客户回访员工，先展示岗位与体验入口，不要发起通话。
帮我打一批客户回访电话，名单我来提供。
看下有哪些外呼任务模板可以选。
为客户回访准备一个外呼任务，先让我确认任务参数。
```

创建、追加联系人与启停任务会先返回预览。确认编号绑定目标和内容，15 分钟内有效；执行确认后同一编号不会重复发送请求，每次提交还携带服务端幂等键（Idempotency-Key）。遇到 `unknown` 状态时先核对操作记录和服务端业务状态，不重传、不重拨。实际拨打条件与费用以 OneCall 当前团队配置为准。

## 使用流程

流程分为两个阶段：**查找与体验**（无需配置，不产生通话与费用）和**外呼实战**（先[配置 API Key](#配置-api-key)，此后所有写操作均为"预览 → 确认 → 执行"）。示例指令可直接发送给已安装本技能的 AI 助手。

### 阶段一：查找与体验（无需配置）

**1. 搜索岗位** — 示例指令：

```text
帮我找一位客户回访员工，先展示岗位与体验入口，不要发起通话
```

返回市场在售的电话员工列表（岗位名、行业、职责简介）及各自的体验入口链接。此步骤不会拨打任何电话。

**2. 查看详情与试听** — 示例指令：

```text
第 1 个不错，给我它的详情和试听入口
```

返回岗位完整介绍与体验页链接（形如 `https://app.16x.tech/market/<岗位名>`）。在浏览器打开链接，按页面要求登录、验证并确认费用后试听。体验均在网页完成，助手不代拨电话、不代为确认收费。

**3. 更换筛选条件（可选）** — 示例指令：`有没有医疗行业的？`。按行业等条件重新筛选，处理方式同第 2 步。

### 阶段二：外呼实战

**4. 配置密钥** — 按[配置 API Key](#配置-api-key) 一节完成，仅首次需要。

**5. 查看模板与任务概况** — 示例指令：

```text
看下有哪些外呼任务模板可以选
```

返回任务模板列表（名称、营销员、时间窗、并发、变量要求）。创建任务必须先选模板；`看下当前的任务列表` 可查询任务与状态（仅呈现任务模板版任务，升级前的历史任务整体隐藏，旧数据请在网页处理）。

**6. 创建外呼任务（预览确认）** — 示例指令：

```text
为客户回访准备一个外呼任务，先让我确认任务参数。模板用客户回访模板，先不自动开始
```

助手先展示该模板的营销员、时间窗与并发供核对，再生成预览（模板、联系人数量、是否自动开始、费用提示），确认后创建（预览 15 分钟内有效）。除非明确同意 `auto_start`，任务创建后不开始拨打；名单可先留空，下一步追加。

**7. 追加联系人（预览确认）** — 示例指令：

```text
导入名单，文件在 ~/leads.json，先别开打
```

名单为 JSON，支持三种等价格式（每次 1–1000 个联系人，`+86` 前缀与空格、横线等自动清理）：

```json
{ "phones": ["+8613800000000", "13890000001"] }
```

```json
{ "data": [ { "phone": "13800000001", "name": "张先生" } ] }
```

```json
{ "contacts": [ { "phone": "13800000001", "name": "张先生", "variables": { "订单号": "A1" } } ] }
```

返回追加预览（号码数量、目标任务当前状态、计费提醒——上传到运行中的任务可能立即拨号），确认后上传；`看下任务里的号码` 可核对结果。**同一号码可以再次上传**：任务中已有的号码重复提交会被受理并生成新的拨打记录（适合"再打一轮"）；同一次上传里出现重复号码则自动去重（受理 1 条，其余标记过滤）。

**8. 启动、暂停与进度查询（均需预览确认）**

| 指令 | 行为 |
| --- | --- |
| `开始外呼` | 确认后启动（`start` 兼具启动与恢复）。服务端先执行启动前检查，条件不满足时返回原因，不会盲目重试。任务刚创建、联系人尚在准备时启动返回 `TASK_PREPARING` 属正常——稍候片刻重试即可 |
| `先暂停` | 确认后停止后续拨打 |
| `现在进度怎么样？` | 返回已拨 / 等待数量 |
| `查一下这个任务的通话记录` | 按任务返回话单（`tasks calls`） |

### 故障处理

| 现象 | 处理方式 |
| --- | --- |
| 提示需要 API Key | 按[配置 API Key](#配置-api-key) 一节配置；密钥不粘贴进对话 |
| 401 / 403 | 核对密钥有效期与权限（`outbound:read` + `outbound:write`） |
| 结果未确定（unknown） | 不重传名单、不重建任务、不重拨试探；先查询任务进度和通话记录核对实际状态 |
| 启动被拒（启动前检查未通过） | 按返回原因补齐员工线路或配置；不修改参数强行重试 |

### 行为约定

1. 查找与试听阶段不产生通话与费用；实际拨号仅发生在确认"开始外呼"之后。
2. 创建任务、导入名单、启停操作均先返回预览，确认后执行；同一确认编号重复提交不会重复发送请求。
3. 助手不代替用户在网页完成登录、验证或付费；返回链接仅表示该步骤在网页进行。

> 以上流程已在真实 OneCall 服务（任务模板版）上完成端到端验证，含任务创建、联系人追加、启动拨打与号码级真实接通（录音、转写、话单回查）。
