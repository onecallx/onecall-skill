# OneCall 电话数字员工 Skill

在支持 Agent Skills 和本地命令执行的 AI 助手中查找电话员工、查询团队通话和任务，并在确认后管理外呼任务。

当前版本 **0.1.0**，协议 **1**。运行环境为 **Node.js 20+**；无第三方运行依赖，无需安装全局 CLI。

## 能做什么

| 功能 | 方式 |
| --- | --- |
| 搜索公开数字员工、查看详情与试听入口 | 直接查询，无需 API Key |
| 创建员工、调整配置、体验语音或电话 | 返回 OneCall 网页入口，在网页完成 |
| 查询团队员工、通话记录、任务与进度 | 使用团队 API Key |
| 创建任务、导入 JSON 名单、启动/恢复/暂停外呼 | 先预览，授权后确认提交 |

## 安装

把这句话发送给支持本地工具执行的 AI 助手：

```text
请帮我安装 OneCall 电话技能：https://github.com/onecallx/onecall-skill
先读取 SKILL.md，保留完整目录。
```

也可以手动克隆到宿主支持的 Skills 目录。下面以 Codex 为例（已有同名目录时先核对本地修改）：

```sh
git clone https://github.com/onecallx/onecall-skill.git ~/.codex/skills/onecall-phonecall
```

Claude Code、WorkBuddy、OpenClaw 的常见目录见[安装与配置](references/setup.md)。Cursor 使用其实际配置的 Skills 目录。安装后重新加载技能或新开对话。仅支持网页聊天、不支持本地命令的工具无法直接运行本 Skill。

## 连接 OneCall

默认连接官方服务，无需配置即可使用：

```sh
node <skill-dir>/scripts/onecall.mjs status
node <skill-dir>/scripts/onecall.mjs market list --q 回访
```

`<skill-dir>` 替换为实际安装目录（各宿主的 Skills 目录见[安装与配置](references/setup.md)）。

公开查询无需密钥。团队操作需要在 OneCall 开发者页面创建 API Key，并在本机配置 `ONECALL_API_KEY`，或通过 `ONECALL_CREDENTIALS_FILE` 指向私密 JSON 文件。不要把密钥粘贴进对话或提交到仓库。`status` 只检查本地配置，不代表服务器授权成功。

本 Skill 依赖服务端的营销员外呼 OpenAPI（`/v1/agents`、`/v1/calls`、`/v1/outbound/*`）。若这些命令返回 `HTTP_410`（`OPENAPI_ENDPOINT_RETIRED`），说明该 OneCall 站点已升级为任务模板版接口，本版本暂不兼容；请核对站点版本，详见[安装与配置](references/setup.md)。

最小权限：员工查询 `assistant:read`；通话查询 `calls:read`；任务查询 `outbound:read`；任务写入还需 `outbound:write`。

## 开始使用

直接用自然语言描述电话业务需求即可触发本技能，无需先提到 OneCall：

```text
帮我找一位客户回访员工，先展示岗位与体验入口，不要发起通话。
帮我打一批客户回访电话，名单我来提供。
查看当前团队的员工和最近通话。
为客户回访准备一个外呼任务，先让我确认任务参数。
```

创建、上传名单与启停任务会先返回预览。确认编号绑定目标和内容，15 分钟内有效。执行确认后，同一编号不会重复发送请求。遇到 `unknown` 状态时先核对操作记录和服务端业务状态，不重传、不重拨；本地防重不等于跨机器服务端幂等。实际拨打条件与费用以 OneCall 当前团队配置为准。

## 使用流程

流程分为两个阶段：**查找与体验**（无需任何配置，不产生通话与费用）和**外呼实战**（首次配置密钥，此后所有写操作均为"预览 → 确认 → 执行"）。示例指令可直接发送给已安装本技能的 AI 助手。

### 阶段一：查找与体验（无需配置）

**1. 搜索岗位**

示例指令：`帮我找一位客户回访员工，先展示岗位与体验入口，不要发起通话`

返回市场在售的电话员工列表（岗位名、行业、职责简介）及各自的体验入口链接。此步骤不会拨打任何电话。

**2. 查看详情与试听**

示例指令：`第 1 个不错，给我它的详情和试听入口`

返回岗位完整介绍与体验页链接（形如 `https://app.16x.tech/market/<岗位名>`）。在浏览器打开链接，按页面要求登录、验证并确认费用后试听。体验均在网页完成，助手不代拨电话、不代为确认收费。

**3. 更换筛选条件（可选）**

示例指令：`有没有医疗行业的？`

按行业等条件重新筛选，结果处理方式同第 2 步。

### 阶段二：外呼实战（首次配置密钥）

**4. 首次配置密钥（仅一次）**

示例指令：`我要用团队功能，API Key 怎么配？`

返回 OneCall 开发者页链接（`https://app.16x.tech/developer`）。配置步骤：

1. **网页创建 Key**：登录后在开发者页创建 API Key（`sk_live_` 开头），按用途勾最小权限——员工 `assistant:read`、通话 `calls:read`、任务 `outbound:read`，要做外呼再加 `outbound:write`。

2. **本机配置**（二选一，密钥只存本机。两个变量名作用不同：`ONECALL_API_KEY` 直接存密钥本体；`ONECALL_CREDENTIALS_FILE` 只存一个指向私密文件的路径）：

   | 方式 | 用的变量 | 密钥实际存哪 | 关掉终端后 | 适合 |
   | --- | --- | --- | --- | --- |
   | A · 环境变量 | `ONECALL_API_KEY` | 只在当前终端内存里 | 失效，要重设 | 临时试一下 |
   | B · 私密文件（推荐） | `ONECALL_CREDENTIALS_FILE` | `~/.onecall/creds.json` 文件（0600 权限） | 文件还在，重开终端只需重设路径变量 | 长期使用 |

   **方式 A · 环境变量**（macOS/Linux，只对当前这个终端窗口有效）：

   ```sh
   # 把密钥本体放进变量；关掉终端就失效
   export ONECALL_API_KEY="sk_live_你复制的密钥"
   ```

   **方式 B · 私密文件**（推荐；技能会校验文件必须 0600，权限不对会拒绝读取）：

   ```sh
   # 1. 建一个自己可见的目录（已存在也不报错）
   mkdir -p ~/.onecall
   # 2. 把密钥写进 JSON 文件（内容必须是 {"apiKey": "…"} 这个结构）
   printf '{"apiKey": "sk_live_你复制的密钥"}' > ~/.onecall/creds.json
   # 3. 收紧权限：仅本用户可读写（必须，权限不对技能会拒绝使用）
   chmod 600 ~/.onecall/creds.json
   # 4. 告诉技能凭据文件在哪（这个变量存的是路径，不是密钥）
   export ONECALL_CREDENTIALS_FILE="$HOME/.onecall/creds.json"
   ```

   **每次自动生效**：方式 A 把 `export ONECALL_API_KEY=…` 写进 `~/.zshrc` 或 `~/.bashrc`；方式 B 把 `export ONECALL_CREDENTIALS_FILE=…` 那一行写进去（注意写的是**路径**，密钥本身留在文件里，别把密钥写进 rc 文件）。

   **Windows**：方式 A 用 `setx ONECALL_API_KEY "sk_live_…"`（写入用户环境变量，新开终端生效）；方式 B 在 PowerShell 里 `$env:ONECALL_CREDENTIALS_FILE="C:\Users\你\.onecall\creds.json"`，文件同样需要仅当前用户可读（icacls 设置），或直接用方式 A。

   **以后换密钥**：网页吊销旧的 → 方式 A 重设一次变量；方式 B 只需替换 `creds.json` 里的密钥内容（权限保持 0600），其他都不用动。

3. **验证**：发送示例指令 `看下配置状态`，返回密钥已配置即完成（权限校验由服务端在首次团队查询时执行）。

安全三原则：密钥**不粘贴进对话**、**不提交进仓库**；疑似泄露时在开发者页**吊销重建**，更换后仅需更新本机配置。

**5. 查看团队概况**

示例指令：`查看当前团队的员工和最近通话`

返回团队员工列表与最近通话记录。

**6. 创建外呼任务（预览确认）**

示例指令：`为客户回访准备一个外呼任务，先让我确认任务参数。营销员用小诗，每天 9 点到 18 点呼，并发 1`

返回任务预览（营销员、时间窗、并发数、费用提示），确认后创建（预览 15 分钟内有效）。任务初始状态为**已暂停**：不会自动开始，且此时不含任何号码。

**7. 导入名单（预览确认）**

示例指令：`导入名单，文件在 ~/leads.json，先别开打`

名单文件为 JSON，支持两种格式（每次 1–100 个号码，`+86` 前缀与空格、横线等会自动清理）：

```json
{ "phones": ["+8613800000000", "13890000001"] }
```

```json
{ "data": [ { "phone": "13800000001", "name": "张先生" }, { "phone": "13800000002", "name": "李女士" } ] }
```

返回导入预览（号码数量、目标任务当前状态、计费提醒——上传到运行中的任务可能立即拨号）。确认后上传。可通过指令 `看下任务里的号码` 核对导入结果（`+86` 前缀自动清理为 `138…`）。

**8. 启动、暂停与进度查询（均需预览确认）**

| 指令 | 行为 |
| --- | --- |
| `开始外呼` | 确认后启动。服务端先执行启动前检查，条件不满足时返回原因，不会盲目重试 |
| `先暂停` | 确认后停止后续拨打 |
| `现在进度怎么样？` | 返回已拨 / 等待数量 |
| `查一下今天的通话记录` | 返回通话列表 |

### 故障处理

| 现象 | 处理方式 |
| --- | --- |
| 提示需要 API Key | 按第 4 步配置；密钥不粘贴进对话 |
| 401 / 403 | 核对密钥有效期与权限（员工 `assistant:read`、通话 `calls:read`、任务 `outbound:read`+`outbound:write`） |
| 结果未确定（unknown） | 不重传名单、不重建任务、不重拨试探；先查询任务进度和通话记录核对实际状态 |
| 启动被拒（启动前检查未通过） | 按返回原因补齐员工线路或配置；不修改参数强行重试 |

### 行为约定

1. 查找与试听阶段不产生通话与费用；实际拨号仅发生在确认"开始外呼"之后。
2. 创建任务、导入名单、启停操作均先返回预览，确认后执行；同一确认编号重复提交不会重复发送请求。
3. 助手不代替用户在网页完成登录、验证或付费；返回链接仅表示该步骤在网页进行。

> 以上流程已于 2026-11-20 完成端到端验证：阶段一逐项对官方线上服务执行通过，阶段二在真实 OneCall 服务上完整执行通过（含任务创建、名单导入、启动前检查拦截与防重提交）。
